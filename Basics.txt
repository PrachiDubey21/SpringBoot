HTTP->
HTTP (HyperText Transfer Protocol) is a communication protocol used to 
transfer information between a client and a server over the internet. 
When we open a website, the browser acts as the client and sends an HTTP 
request to the server. The server processes the request and sends an HTTP 
response back to the browser. HTTP is not encrypted, which means the data being 
transferred can potentially be intercepted and read by an attacker. 
Therefore, HTTP is not considered secure for sensitive information such 
as passwords, banking details, or personal data.

It tells request / response structure , how data will be send
by default (non encrypted)
--> GET , POST , DELETE , PUT , PATCH  (calls)



HTTPS->
HTTPS (HyperText Transfer Protocol Secure) is the secure version of HTTP. 
It is used for communication between a client and a server while protecting 
the data through encryption using TLS (Transport Layer Security). 
When a user sends sensitive information through an HTTPS connection, 
the data is encrypted before being transmitted, making it much harder for 
attackers to read or modify. Websites using HTTPS generally have a URL 
beginning with https:// and display a lock symbol in the browser.

(encrypted)

Spring Framework

Spring Framework is an open-source framework for developing Java applications. 
It provides a set of tools and features that make it easier to build large, 
flexible, and maintainable applications. One of its main features is 
Dependency Injection (DI), where Spring manages the creation and dependencies 
of objects instead of the programmer creating them manually. 
Spring also provides features for developing web applications, 
working with databases, handling transactions, security, and more.

The Spring Framework is based mainly on the concept of IoC (Inversion of Control), 
which means that the control of creating and managing objects is given to the 
Spring container. Objects managed by Spring are called Spring Beans. 
Spring is modular, so developers can use only the features they need.

In simple words, Spring Framework makes Java application development easier 
by managing objects, reducing tightly coupled code, and providing ready-made 
features for common application requirements.

Spring Framework vs Spring Boot -->
Spring Framework is the main framework that provides features such as 
Dependency Injection, IoC, database support, web development, and security. 
Spring Boot is built on top of Spring Framework and makes Spring application 
development easier by providing auto-configuration, starter dependencies, 
and embedded servers, so much less configuration is required.

                              MAVEN

Maven is a build and dependency management tool for Java projects.
In simple words, Maven helps us manage everything needed to build and run a 
Java/Spring Boot project, such as downloading libraries, compiling code, 
running tests, and packaging the application.

Think of Maven as a project manager for your Java project. Instead of 
manually downloading and managing every library, Maven does it for you.


Without Maven, you would have to:
Find the required JAR files.
Download them.
Add them to your project.
Make sure compatible versions are used.
Download other libraries that those libraries depend on.
Manage all of this whenever you update your project.


Maven Maintains
   -> folder structure
   -> helps in compile
   -> creates JAR code
   -> Downloads dependencies

---------------------------------------------------------------------------------

POM = Project Object Model
It contains information about your project, including its dependencies.

It is an XML file used by Maven to describe and manage a Java project.

The pom.xml file contains important information about the project, 
such as the project name, version, Java version, dependencies, plugins, 
and build configuration.

The most important use of pom.xml is dependency management. 
If a project requires external libraries such as Spring Boot, 
Maven reads the dependencies mentioned in pom.xml and downloads 
the required libraries automatically.

For example, in a Spring Boot project, if we need Spring Web, 
its dependency is added to pom.xml. Maven then makes the required 
Spring Web classes available to the project.

It also helps Maven perform tasks such as compiling the code, 
running tests, packaging the application, and building the project.

pom.xml is the configuration file of a Maven project that defines 
project information, dependencies, plugins, and build settings.

--------------------------------------------------------------------------------

JAR stands for Java ARchive.
A JAR file is basically a compressed package that contains Java code and 
other files needed to run an application or provide a library.
Think of it like a ZIP file for Java.

Advantages of JAR

Easy to distribute – Instead of sharing many .class and resource files separately, 
we can package them into one JAR file.

Easy to run – A Java application can be run using:
java -jar application.jar

Smaller size – JAR uses compression, so it can reduce the size 
of the packaged files.

Keeps files organized – Java classes, configuration files, images, a
nd other resources can be kept together in one package.

Reusable – A JAR can be used as a library in other Java projects.

Easy deployment – In Spring Boot, the application can be packaged as a JAR 
and deployed to a server easily.




A Library JAR contains reusable Java code that another application uses.

An Application JAR contains a complete Java application that 
is meant to run by itself.



Classpath is the location/path where Java looks for the classes and libraries 
required to run or compile a program.
In very simple terms:
Classpath tells Java: "Where should I look for the .class files and JAR 
files that I need?"

--------------------------------------------------------------------------------

target/

                             MAVEN LIFECYCLE

Definition
Maven Lifecycle is a predefined sequence of steps that Maven 
follows to build and manage a Java project. It defines the different 
stages of the build process, such as validation, compilation, testing, 
packaging, installation, and deployment.

Maven has three standard lifecycles: Clean, Default, and Site.


1. Clean Lifecycle
The Clean Lifecycle is used to clean the project by removing 
files generated during previous builds.

The main phases are:
pre-clean → clean → post-clean

The most commonly used command is:
mvn clean

In our project, we can use:
.\mvnw.cmd clean

The clean phase generally removes the target directory.



2. Default Lifecycl
The Default Lifecycle is the main lifecycle used for building a Maven project.

Important phases are:

validate
   ↓
compile
   ↓
test
   ↓
package
   ↓
verify
   ↓
install
   ↓
deploy

Validate -> The validate phase checks whether the project is correctly 
configured and ready for the build process.
mvn validate

Compile -> The compile phase compiles the Java source code into .class files. 
.java files → .class files
mvn compile

Test -> The test phase runs the tests written for the project.
mvn test

Package -> The package phase packages the compiled application 
into a distributable format such as a JAR.
mvn package
For a Spring Boot application, the JAR is generally created 
inside the target folder.

Verify -> The verify phase performs additional checks to verify 
that the project meets the required conditions.
mvn verify

Install -> The install phase installs the packaged project 
into the developer's local Maven repository.
mvn install
The local Maven repository is generally located at:

C:\Users\<username>\.m2\repository

Deploy -> The deploy phase uploads the packaged project 
to a remote Maven repository so that it can be shared with other 
developers or projects.
mvn deploy


3. Site Lifecycle

The Site Lifecycle is used to generate documentation and reports 
for a Maven project.

Its main phases are:
pre-site → site → post-site → site-deploy

It is mainly concerned with project documentation rather than 
building the application.

Important Rule -> 
Maven executes the phases that come before the phase you specify.

For example, if you run:
mvn package

Maven performs:

validate
   ↓
compile
   ↓
test
   ↓
package

If you run:
mvn install

Maven performs the required earlier phases and then install.

Therefore: A later Maven phase automatically includes the 
required earlier phases.

Maven Lifecycle and Spring Boot

In our Spring Boot project, we use:
.\mvnw.cmd spring-boot:run

spring-boot:run is not a Maven lifecycle phase. It is a goal 
provided by the Spring Boot Maven Plugin.

So:
Maven Lifecycle
→ compile
→ test
→ package
→ install
→ deploy

while:

Spring Boot Maven Plugin
→ spring-boot:run
→ starts the Spring Boot application
